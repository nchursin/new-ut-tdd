# Паттерны тестируемого дизайна
Timing: 30 min
## Флип: Тестируемый дизайн
- Итеративный эволюционный дизайн
  - Пример: Лунная программа развивалась по шагам: запуск человека на орбиту, запуск непилотируемого аппарата на орбиту Луны, посадка на Луну, пилотируемый полет на Луну
- Используйте бережливый подход: KISS, YAGNI, DRY
- Разделение ответственностей
  - Одна причина для изменения - единая ответственность
  - Разделение создания и логики (сборка автомобильного двигателя и эксплуатация двигателя — две разные ответственности)
  - Bounded Context
- Закон Деметры: "разговаривайте со своими друзьями, а не с незнакомцами"
  - Покупатель - Кассир - Кошелек - 100р
  - Пример на проекторе TODO
- Заменяйте ifs/switch полиморфизмом
- Скрывайте сложность
  - Часы: простой и доступный для каждого интерфейс, сложный механизм внутри
- Разработка через типы Type Driven Development
- DI (Dependency Inversion) - инверсия зависимостей
  - Пример на проекторе TODO
- ООП ([правила гимнастики объектов](https://williamdurand.fr/2013/06/03/object-calisthenics/)) или Фукциональная парадигма ([правила функциональной гимнастики](https://www.codurance.com/publications/2017/10/12/functional-calisthenics))
- Четыре принципа простого дизайна
   - Код покрыт тестами и они все проходят
   - Код выразителен и раскрывает наши намерения
   - Минимум дублирования
   - Минимум элементов и объема
- Принцип сбалансированных абстракций: на каждом уровне код должен придерживаться одинакового уровня абстракций
   - Инструкции в методе
   - Публичные классы метода
   - Классы в модуле
   - Модули / пространства имен внутри модуля
- Принцип наименьшего удивления (Принцип WTF)
