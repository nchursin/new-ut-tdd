## Флип: Парное программирование

- Драйвер - тактика, "руки", пишет код здесь и сейчас

- Все преимущества Code Review, но без задержек
- Качественная и быстрая обратная связь
- Сфокусированная работа
- Качественный результат
- Обмен знаниями
- Соблюдение договоренностей
- Устаешь как пёс, зато кайфуешь от результата

## Флип: Характеристики хорошего модульного теста
- Понятный
    - Название
    - Структура
    - Данные
    - Тестирует поведение, понятное пользователю, а не реализацию
- Независимый
    - От других тестов
    - От порядка выполнения
    - От окружения
- Быстрый
- Сфокусированный
    - Проверяет одну трассу выполнения
    - Если упал, сразу понятно что именно сломалось
- Стабильный
    - Выдает один и тот же результат
- Автоматический
    - Запуск одной кнопкой
- Актуальный
    - Тестирует то, что будет важно и завтра
- Легкий в написании

## Структура AAA
### Флип: Структура AAA
- Assert
- Act
- Arrange
   
**Правила**
- 1 Act
- 1 Assert или как минимум 1 концепция на тест

### Проектор
```python
# одна концепция и одна проверка на тест

def test_win_on_three_x_horizontally():   # 4ый шаг: название теста
    game = Game("XX \nOO \n   ")          # 3ий шаг: подготовка данных (arrange)

    status = game.play_x(Position.P1_3)   # 2ой шаг: действие (act)

    assert status == Status.WIN           # 1ый шаг: проверка результата (assert)
```

## Наименование
### Флип: Название теста
- сфокусированное на пользователе
- пишите имя в конце, если сложно начать
- используйте конкретные примеры в названии теста
- можно использовать нотацию given when then
